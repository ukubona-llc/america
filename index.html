# Upstream of $P_{baseline}$

Round I located the risk in $P_{baseline}$ and $\gamma$—parameters you can version and audit after the fact. This round shows it starts earlier, in the choice of state variables themselves.

DemographicAnxiety in Google's actual code, SelectionQuality in xAI's text—neither is a measurement, both are conclusions with a variable name on them.

The Three-Question Test

A workable gate: nothing enters the state vector $S_t$ unless it can cleanly answer three questions:

  • Who measured it?
  • How was it measured?
  • What does its known error and bias look like?

"Share of respondents citing immigration as a top concern, Pew, $\pm3\%$" passes that test. SelectionQuality doesn't, because no instrument produces it—it's the causal story, pre-loaded into the variable name. If a dimension's name already contains its own verdict, it doesn't get to sit in $S_t$.

Here is what that gate looks like in the ingestion path, enforced ahead of compute_jacobian:

class StateVariable(BaseModel):
    name: str
    measured_by: str
    methodology: str
    error_margin: float
    value: float

    @validator('name')
    def enforce_neutral_naming(cls, v):
        """
        If a dimension's name already contains its own verdict, 
        it doesn't get to sit in S_t.
        """
        ideological_markers = ['quality', 'anxiety', 'dysgenic']
        if any(marker in v.lower() for marker in ideological_markers):
            raise ValueError(f"Variable '{v}' contains a verdict, not a measurement.")
        return v

def ingest_state_vector(raw_inputs: List[dict]) -> np.ndarray:
    validated_vars = []
    for raw in raw_inputs:
        # The Three-Question Gate
        var = StateVariable(**raw) 
        validated_vars.append(var.value)
    return np.array(validated_vars)
